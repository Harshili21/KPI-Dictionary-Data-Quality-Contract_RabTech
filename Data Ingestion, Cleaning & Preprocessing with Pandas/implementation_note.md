## 1. Executive Overview

Real-world business databases rarely store perfectly clean data. Raw transaction streams generated by web applications, point-of-sale systems, and third-party payment providers frequently suffer from duplicate submissions, mixed currency formatting, inconsistent date serialization, missing values, and corrupted data types.

This project delivers a comprehensive, production-grade **Data Ingestion, Cleaning & Preprocessing Pipeline** using **Python and Pandas** on a real-world **12,850-row business dataset**. The pipeline transforms dirty transactional records into an enterprise-ready analytical dataset (`clean_dataset.csv`) enriched with 11 domain-specific engineered features.

---

## 2. Source Data Ingestion & Diagnostic Profiling

The raw dataset (`raw_business_dataset.csv`) was synthesized to mirror authentic multi-channel retail operations spanning 5 product categories (Electronics, Home & Kitchen, Clothing & Apparel, Beauty & Personal Care, Books & Stationery).

### Initial Diagnostic Profiling:
- **Dimensions:** 12,850 rows $\times$ 17 columns.
- **Duplicate Rows:** 350 duplicate transactions generated by simulated API retry bursts.
- **Missing Value Impact:** Over 2,100 null cells distributed across `Customer_Age`, `Customer_Gender`, `Customer_Region`, `Quantity_Ordered`, `Unit_Price`, `Discount_Applied`, and `Shipping_Cost`.
- **Schema Violations:**
  - `Unit_Price` contained string currency symbols (`$`, `€`), commas, and negative values.
  - `Quantity_Ordered` contained word strings (`'two'`, `'three'`), negative quantities (`-1`), and extreme numeric spikes ($> 200$).
  - `Discount_Applied` contained percentage strings (`'10%'`) and invalid values ($> 100\%$).
  - `Order_Date` and `Ship_Date` mixed ISO (`YYYY-MM-DD`), European (`DD/MM/YYYY`), US (`MM-DD-YYYY`), and unparsable calendar dates (`2025-02-31`).
  - Temporal incoherence where `Ship_Date < Order_Date`.

## 3. Step-by-Step Data Cleaning & Remediation Methodology

### Step 1: De-duplication & Identifier Sanitization
- Trimmed whitespace from `Transaction_ID` and `Customer_ID`.
- Executed `drop_duplicates(subset=['Transaction_ID'], keep='first')`, removing 350 duplicate rows and preserving transaction uniqueness.

### Step 2: Robust Type Casting & Currency Normalization
- **Currency Cleaning:** Created regex parser to strip symbols (`$`, `€`, `,`), coerce strings to positive floats, and handle negative prices.
- **Quantity Cleaning:** Mapped word numbers (`'one'` $\rightarrow$ 1, `'two'` $\rightarrow$ 2) and coerced strings to integer values.
- **Discount Standardization:** Normalized percentage strings (`'10%'` $\rightarrow$ 0.10) and decimal fractions into a bounded range $[0.0, 0.70]$.

### Step 3: Multi-Format Date Parsing & Temporal Logic Repair
- Developed a multi-format date parser cascading through ISO, British, and US datetime formats.
- Handled invalid calendar dates and dropped irrecoverable missing order dates.
- Imputed missing ship dates using median fulfillment lag (`Order_Date + 3 days`).
- Corrected negative fulfillment duration where `Ship_Date < Order_Date` by enforcing `Ship_Date = Order_Date + 2 days`.

### Step 4: Missing Value Imputation Strategy
- **Numeric Fields:**
  - `Quantity_Ordered`: Group-level median imputation based on `Product_Category`.
  - `Unit_Price`: Group-level median imputation based on specific `Product_Name`.
  - `Customer_Age`: Group-level median imputation by `Product_Category`.
  - `Shipping_Cost`: Global median imputation ($5.99).
- **Categorical Fields:**
  - `Customer_Gender`: Imputed missing as `'Other'`.
  - `Customer_Region`: Imputed missing as `'Unknown'`.
  - `Payment_Method`: Imputed missing as `'Credit Card'` (mode).
  - `Order_Status`: Imputed missing as `'Delivered'`.

### Step 5: Outlier Remediation & Capping
- **Customer Age:** Clamped to realistic adult demographic bounds $[18, 90]$.
- **Quantity Ordered:** Detected extreme transaction spikes using Interquartile Range (IQR) and capped at $Q_3 + 2.5 \times \text{IQR}$ (maximum 20 units).
- **Unit Price:** Winsorized upper price bounds at $Q_3 + 3.0 \times \text{IQR}$.

### Step 6: Categorical Normalization & Entity Harmonization
- Standardized country names using dictionary mapping (`USA`, `U.S.A.`, `united states` $\rightarrow$ `United States`; `UK`, `U.K.` $\rightarrow$ `United Kingdom`; `IN` $\rightarrow$ `India`; `CA` $\rightarrow$ `Canada`).
- Standardized gender values (`M`, `m` $\rightarrow$ `Male`; `F`, `f`, `FEMALE` $\rightarrow$ `Female`).
- Normalized payment methods and order statuses to Title Case.

## 4. Advanced Feature Engineering

The dataset was enriched with 11 domain-specific business features:
1. **Time Dimensions:** `Order_Year`, `Order_Month`, `Order_Month_Name`, `Order_Quarter`, `Day_of_Week`, `Is_Weekend`.
2. **Fulfillment Metric:** `Delivery_Duration_Days` ($\text{Ship\_Date} - \text{Order\_Date}$).
3. **Financial Metrics:**
   - $\text{Gross\_Sales\_Amount} = \text{Quantity} \times \text{Unit\_Price}$
   - $\text{Discount\_Amount} = \text{Gross\_Sales} \times \text{Discount\_Applied}$
   - $\text{Net\_Sales\_Amount} = \text{Gross\_Sales} - \text{Discount\_Amount}$
   - $\text{Total\_COGS} = \text{Quantity} \times \text{Unit\_Cost}$
   - $\text{Gross\_Profit} = \text{Net\_Sales} - \text{Total\_COGS}$
   - $\text{Profit\_Margin\_Pct} = (\text{Gross\_Profit} / \text{Net\_Sales}) \times 100$
4. **Behavioral Cohorts:** `Customer_Age_Group` (`Gen Z`, `Millennial`, `Gen X`, `Boomer+`) and `Order_Value_Tier` (`Budget`, `Standard`, `Premium`, `VIP Enterprise`).
